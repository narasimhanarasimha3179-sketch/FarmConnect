# FARMCONNECT
## Master Project Development Roadmap – Phase 0 to Phase 32

**Project:** FarmConnect – Smart Agricultural Products & Market Assistance Platform

**Vision:** Build a complete, professional, secure, scalable Android-first agriculture platform connecting Farmers, Buyers, Sellers and Administrators.

**Development approach:** Incremental development, phase-by-phase, with permanent feature preservation.

# PART 2 – STRICT ANTIGRAVITY DEVELOPMENT RULES

These rules apply to ALL 33 phases.

## RULE 1 – ONE PROJECT ONLY
FarmConnect must remain one continuous application.
Never create separate applications for individual phases.

## RULE 2 – NEVER DELETE PREVIOUS FEATURES
Every new feature must be integrated with all existing features.
Old features + new features = updated application.
Never replace the application with only the latest feature.

## RULE 3 – INSPECT BEFORE EDITING
Before modifying any file:
- Read the existing file.
- Understand its functionality.
- Identify dependencies.
- Identify connected components.
- Identify API connections.
- Identify affected routes.

## RULE 4 – NO UNAUTHORIZED DELETIONS
Never delete existing files, components, routes, database models or features without explaining the reason and receiving my explicit approval.

## RULE 5 – INCREMENTAL DEVELOPMENT
Work on one small development step at a time.
Do not generate the entire application in one response.

## RULE 6 – TEST PREVIOUS FEATURES
After every implementation, test:
1. Existing features.
2. New feature.
3. Navigation.
4. API integration.
5. Database operations.
6. Role permissions.
A new feature is not complete if an old feature stops working.

## RULE 7 – PERMANENT DOCUMENTATION
Maintain these files:
- docs/FARMCONNECT_MASTER_ROADMAP.md
- docs/FARMCONNECT_PROGRESS.md
- docs/PROJECT_BASELINE.md
- docs/CHANGELOG.md
- docs/ARCHITECTURE.md
- docs/KNOWN_ISSUES.md

Never delete or shorten the master roadmap.
Update progress after every completed step.
Append to the changelog rather than deleting history.

## RULE 8 – GIT CHECKPOINTS
Check Git status before major changes.
Create meaningful commits when appropriate.
Never run destructive commands such as git reset --hard or git clean -fd without explicit permission.

## RULE 9 – REAL INTEGRATIONS ONLY
Never claim that a feature is live if it uses mock data.
Clearly identify:
- Real API.
- Mock API.
- Placeholder.
- Pending integration.
Keep API keys and secrets on the backend.

## RULE 10 – NO RANDOM REBUILDING
If an error occurs, diagnose and repair the existing implementation.
Never rebuild the application to fix a small issue.

## RULE 11 – ANDROID-FIRST
FarmConnect must work well on Android phones.
Support:
- Different screen sizes.
- Touch interactions.
- Low-end devices.
- Slow internet.
- Camera permissions.
- Location permissions.
- Secure storage.
- Offline/error states where appropriate.

## RULE 12 – STOP AFTER EACH STEP
After completing one step:
1. Explain what changed.
2. List files created.
3. List files modified.
4. Explain tests performed.
5. Report old feature preservation.
6. Update the roadmap.
7. State the next step.
8. Stop and wait for my confirmation.
I will reply DONE when I am ready for the next step.
